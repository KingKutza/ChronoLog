- (8.27) ENTAILMENT STATED BACK (engine build, 2026-08-27, standing unless Don objects): the projection algebra needed one rule the boolean ruling did not state, derived from "cross-frame projection only through staples": a PLACEMENT locates a fact and does not carry the object's other facts — an object on two calendars does not relate those calendars, so its calendar-A fact never draws on calendar B; reached through a STAPLE it is the opposite claim (the author connected them, "so we can project the two relative to each other"), so a stapled far object's placements DO count, one hop out. Without this rule OR-is-union and AND-is-intersection fail on random worlds — the algebra is not self-consistent. Companion choice: a projection's universe is the OR of every frame it names, negated ones included, so `NOT b` alone selects nothing rather than everything and De Morgan holds on populations. REFINED BY DON (2026-08-27), the governing vocabulary — CONNECTION IS NOT INCLUSION: "an event on two frames does connect them but does not include them. If a' is on A and B, and I project A I get a' but not B; if I project B I get a' but not A; if I project A and B then I get A, B, and a' — and A and B are connected at a'. This is the Lines lens in action: it shows the shape of the flow of time across multiple [frames] based on where they attach." So a shared placement IS a real edge in the connection graph — Lines draws it, weight traverses it, the Tree lens will show it — while projection includes only by naming. The engine's population behavior already matches all three of Don's cases; its comment wording ("does not relate those calendars") is corrected to this vocabulary.
