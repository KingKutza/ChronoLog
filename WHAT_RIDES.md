## Decisions needing Don's ruling

1. **The budget itself.** Options: (a) hold 10k, ship the assembly above — recommended; (b) move the ceiling and ship the full ruled target in one pass (~11k); (c) hold 6k and name the ruled capabilities that don't exist in pass one. The line counts are estimates; the warden enforces whatever is ruled.
2. **Does editing the plaintext file count as the authoring path** for coordinate-law structure, weight formulas, patterns, themes, and settings? The app validates, reports refusals in the law's own vocabulary, and hot-reloads the file; the GUI keeps read views and escape hatches but not full form editors in pass one. Worth −490 and it is the Obsidian posture taken seriously — but it cuts against "no raw literals" and "every relation has a GUI path," so it cannot be decided on budget alone. Recommended: yes for law/formula/pattern/theme/settings; no for staples, containment, and objects, which keep real GUI authoring.
3. **X-CHRONOLOG dialect dies — accept the named fidelity loss.** Killing it (~315 JS lines, a third of ics.js) is already ruled; the consequence not yet accepted in these words: object anchors, fuzzy spreads, and segmented-series identity stop round-tripping through ICS. Recommended export shape: segmented series emit as plain sibling VEVENTs with correct times, identity lost — "rules-or-projections out" honored literally. Source identity for multi-calendar sync gets a non-dialect carrier (source-URL hash).
4. **The formula language narrows to basic algebra** — numbers, `w`, arithmetic, comparisons, ternary, min/max/abs/floor/ceil (751 JS → 140 Dart). It is currently a sandboxed programming language with exactly one consumer: multiplying a weight. Your ruling verbatim: "if I can describe with basic algebra how membership should alter a member, then I should be able to do that." Recommended: narrow. Kills three unreachable formula paths and the fixed-point trig with it.
5. **Time-travel taxonomy: live design or absorbed?** Four relation types (`shared-segment`, `termination`, `displacement`, `coordinate-mapping`) have validators, one fixture, zero authoring paths. Correspondence staples and eras-as-stapled-frames now carry what coordinate-mapping was designed for; only Lines reads two of the others. This is designed LEXICON vocabulary, not accident — your call: 0 vs ~130 Dart plus authoring surfaces. Lines' authored-topology drawing rides either way.
6. **Record-type codegen** (`freezed`/`build_runner`): generated files outside the budget, ~300-line swing, one added build step on the Android pipeline. Recommended: yes. Must be decided before the first record class is written.
7. **Lens canon: nine.** Ratify the count so tests stop disagreeing (docs and two tests still say seven; the catalog and three tests say nine; Spiral/Radial separateness is upheld everywhere).
8. **Lens auto-swap dies.** Today zooming silently swaps Intimate→Tactical→Strategic through two magic thresholds. In the tiling model a pane *is* a lens. Visible behavior change. Recommended: die.
9. **One magnitude-driven overscale budget** replaces the 13 scattered per-lens truncation caps, and the radial lenses' hard 5-lane cap dies to apparent-magnitude falloff. Recommended: yes.
10. **Falloff generalizes** from its single hardcoded call site into the standard input to display weight. Ordering needs a ruling because mixed +/× don't commute: recommended — falloff applies after the frame-formula fold, multiplicatively, documented as contract.
11. **Zone fill: lens knob or group display property?** Currently a per-lens session boolean; frames-are-groups suggests it may belong to the group. Also: `strategicMode` (signal/blocks/all with a hardcoded 240-minute threshold) looks like a second mechanism for what importance thresholds already express — keep or melt?
12. **Multi-process editing over one file: not a pass-one requirement.** The journal file and record-level merge ride; the HTTP server, 409-rebase loop, and multi-window toast die. Recommended: single instance per document in pass one.

## Rulings from Don's review (2026-08-27)

1. **Budget: held pending the unified-math answer** — Don is "willing and ready to authorize the 13k build"; final word follows the block-list/one-math response. 2. **Plaintext editing is a valid path and hot-reloads, AND no user should need to edit a file to use any feature** — GUI editors ride in the full build; the file is an always-valid second path, never the only one. 3. **Live ICS dies** — "we can import and export but we do not need to be beholden while using the app"; subscription feeds/auto-pull are out, file import/export rides. (X-dialect round-trip loss CONFIRMED by Don 2026-08-27: a fresh import of an exported file gets correct times, no staples, segmented series as separate plain events.) 4. **One math, used everywhere** — the boolean projection algebra, weight formulas, falloff, and future time-flow functions are one expression language, one parser, one evaluator. 5. **Time travel is a native first-class citizen and will not be demoted** — the hardcoded taxonomy validators still die as-written, but the capability is re-founded on the one math: define a function, and one projector projects it. 6. **Non-core platform/binary-generation code is outside the budget, same as tests** — record codegen approved, generated files uncounted. 7. **Generative testing ruling** — never validate an arbitrary fact (no lens-count assertions; the count is in flux); test general properties over seeded random generation (random non-Gregorian frames, random events, n+1 invariance). The seven-vs-nine question dissolves. 8. **Lens auto-swap: kill it dead.** 9. **No arbitrary integer caps** — lens capacity is screen space + magnitude falloff + sigils; one derived budget. 10. **Weight composition chain BLESSED (Don, 2026-08-27):** nesting, inside out — (1) the object's own authored math; (2) connected modifying frames by increasing graph distance, nearest first; (3) ties at equal distance broken deterministically by stable id (meaningless, just stable); (4) the projecting frame/expression last among frames — uniform monotone math applied last cannot reorder the view, which is what "matters least" requires; (5) apparent-magnitude falloff as the projector's own closing step. NOT-terms gate visibility and never modify weight. Weight is projection-relative by design. The inspector's derivation explainer shows every ring. 11. **Zone fill melts to a group property** — and the general principle recorded: "Enum is the enemy… any system that encodes a right way does in the same breath preclude other ways." Nothing is special about the default path; a staple's type and a frame's nature are relative to the projection. 12. **Process/threading left to the coordinator** — ruled: one master isolate owns the document and journal (single writer), window/pane children read through it; projection work may fan to worker isolates under overscale; no HTTP, no rebase loop. **Deletions: all signed** — "code that is not used is not used and should be removed."

Consequences folded in: eras are not a block (era tables are frame law data; era chains are succession-staple traversal — the module folds into frames/coordinate-law); the formula engine doesn't merely narrow, it becomes THE math serving projection + weight + falloff; live-feed machinery (−520) leaves the build. Revised full-build estimate: **≈ 12,000–12,500**.
